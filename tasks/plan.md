# TRadar 首版实施计划

2026-10-14。用户连续要求进入下一步，按既定能力范围实施；不扩大到公网发布或付费服务。
规格入口：`docs/spec-overview.md`，六份 `SPEC-*.md` 是行为基线，完成情况以 `tasks/todo.md` 记录。

## 方法与架构

采用 agent-skills 的 planning-and-task-breakdown、incremental-implementation 与 TDD。
先跑有意义的失败用例，再完成一个小切片，测试与运行验证后提交。当前由主代理顺序推进。
先打通空库→人工项目→浏览器查看的最小路径，再扩展证据和采集，避免只完成横向脚手架。

Go 单进程 + SQLite；React 构建静态资源由 Go 同源提供，开发 Vite 反向代理到 Go。
领域模型按模块分包；HTTP 与数据库基础设施集中，迁移版本化。
持久化事务接口显式传入，幂等结果与变更同事务；异步任务先提交意图再访问外部依赖。
数据库只保存在本地，默认地址回环，允许 SSH 隧道访问。模型只接受公开证据，不执行工具。

## 切片与验证点

1. 基础工程、存储、URL 身份、创建/读取项目 API，配中文空状态和录入界面。
2. 项目证据、来源身份与观测写入，验证幂等、回滚、重启和编辑冲突。
3. 真实 GH/HN 采集任务、来源设置、预算/调度，再加 PH 条件适配；网络只在显式采集时访问。
4. 增长/排序→雷达页面；固定时钟用例覆盖缺样、日桶、下降、加速度和持续性。
5. 人工与规则分析→研究笔记/实验→日报快照/导出；各业务路径单独集成验证。
6. 可选模型适配及预算，默认关闭；使用假提供者证明失败和引用边界，不消耗用户模型额度。
7. 浏览器完整流程、故障/安全审查、构建/文档/备份/运行时验收。

任务详情与文件边界写在 todo；每完成两三个任务设置集成检查点。
只将通过了对应证据检查的任务打勾，不能以文档存在证明功能完成。

## 风险与处置

| 风险 | 处置 |
|---|---|
| Github/PH 接口、权限或限额变化 | 文档依据+可控适配器测试+独立实时冒烟；保留原错误，不假称接通 |
| 规模尚小但规格边界多 | 每步验证最小闭环；保留全部验收项，不删测试换取通过 |
| 多窗口和日界错配 | 数据 basis、periodKey 和窗口独立；注入时钟，测试断采与负增长 |
| 同源服务被外部页面访问 | Host/Origin/JSON 输入边界；回环默认；敏感信息不出现在响应 |
| 模型输出错误 | 引用和结构校验、原始来源与版本保存，失败不降级成成功 |
| 并发或进程中断 | 事务/唯一约束/ETag，任务重启标记中断，预算不因重启归零 |

非阻塞配置：PH Token、模型提供者/预算、将来的服务器地址。缺失时界面明确未启用。
验证记录保存在 `docs/verification.md`；架构变更及时同步对应规格。
