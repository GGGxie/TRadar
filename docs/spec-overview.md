## 六个模块规格

| 模块 | 规格 | 本模块解决的问题 |
|---|---|---|
| `project-catalog` | [项目目录](../SPEC-project-catalog.md) | 项目身份如何合并、证据与快照如何保留、错误关联如何纠正 |
| `source-ingestion` | [信息采集](../SPEC-source-ingestion.md) | 如何定时发现项目、持续观测、控制配额并处理局部失败 |
| `trend-ranking` | [趋势排序](../SPEC-trend-ranking.md) | 如何诚实计算增速、加速度、持续性，并解释排序 |
| `project-analysis` | [项目分析](../SPEC-project-analysis.md) | 如何形成带证据的初筛与六维分析，如何接入可选模型 |
| `research-workspace` | [研究工作台](../SPEC-research-workspace.md) | 如何保存个人判断、未知问题、实践结果，避免模型覆盖笔记 |
| `daily-brief` | [每日简报](../SPEC-daily-brief.md) | 如何形成去重、可回溯、有日期边界的站内简报及导出 |

[共享规格](spec-common.md) 集中定义技术栈、项目结构、目标命令、通用 API、测试策略与运行边界；

## 建议优先审阅的决定

1. **使用与部署**：个人中文 Web 应用，Go + React/TypeScript + SQLite，本机运行、默认回环访问。
   首版的实际通知交付物为站内每日简报与 Markdown 导出。
2. **信息源**：GitHub/HN 自动采集；PH 有凭据后接入；商业访谈及其他链接可人工录入。
   首次采集和缺少历史都单独显示，不把空白补成虚构增长。
3. **可信度**：事实必须关联来源及时间；创始人收入声明保留为自述；模型只整理现有证据，
   没证据时列为假设或未知。没有模型也能运行基础闭环。
4. **研究深度**：3 分钟初筛、30 分钟六维研究、3 小时以上人工实践。
   系统记录实验和决策，不自动执行陌生项目或替用户验证付费意愿。
5. **一致性**：采集可重试、日报版本冻结、编辑有版本冲突保护；个人判断归用户所有。
