## 4. 运行验证记录

本任务主要交付操作命令和文档，没有新增领域业务逻辑，因此不为 Makefile 文本编写镜像其实现的单元
测试。验证改用真实运行路径：在 `/tmp` 创建不含 `.git`、`node_modules`、`web/dist`、`bin`、`data`
和 `backups` 的隔离副本，依次执行 `make setup`、`make build`，再用独立数据库启动产物。

运行结果：

- npm 从锁文件安装 115 个包，Go 模块按 `go.sum` 下载；
- Vite 生成生产静态文件，Go 生成 `bin/tradar`；
- `GET /healthz` 返回 `{"data":{"status":"ok"}}`，`GET /radar` 返回 200 和 HTML；
- 空库自动迁移到 schema 10，`PRAGMA quick_check` 返回 `ok`；
- 发送 SIGINT 后进程正常退出，退出码为 0。

对操作目标另外创建带 WAL 的临时 SQLite 数据库。`make backup` 保存备份时的 `before-backup`，随后原库
改为 `after-backup`；恢复出的数据库仍读到 `before-backup`，证明取得的是一致时间点快照。备份和恢复文件
权限均为 0600，quick check 为 `ok`。没有 `CONFIRM_RESTORE=yes` 时命令以非零退出并拒绝覆盖；已有目标
被覆盖前会生成 `.before-restore-<UTC>` 副本。

## 5. 问题、根因与修正

| 现象 | 根因 | 修正与防回归 |
|---|---|---|
| 隔离副本首次 Go 构建无法写默认 cache | Codex 沙箱不允许向 `/root/.cache` 写入 | 仅在验证命令传入 `/tmp` GOCACHE；这是执行环境约束，不写入用户 README |
| 改用可写 cache 后，脱离 `.git` 的构建报 VCS status 128 | Go 默认尝试为主模块写入 VCS build info；发布目录没有仓库元数据 | Makefile 增加 `-buildvcs=false`，保持 `-trimpath`；同一隔离目录重建成功 |
| 只复制 WAL 模式主文件可能丢失已提交内容 | WAL 页不保证已 checkpoint 到主文件 | `make backup` 使用 SQLite `.backup`，完成后做 quick check，不提供简单 `cp` 备份命令 |

`.env.example` 不含秘密且不会被程序隐式加载，避免“文件存在就自动启用外部调用”。README 明确要求
由 shell 或进程管理器导出；provider 留空、调度关闭和空库都是安全默认值。
